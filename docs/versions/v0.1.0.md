# Showup v0.1.0

**Release date:** 2026-10-12
**Status:** MVP / prototype

## Purpose

Prove the core interaction: save a gym, press one button at the gym, and see a counter go up only when you're actually there. Everything else is deferred.

## Implemented features

- Temporary demo profile (username kept, password discarded); session restored on reload
- Google Maps gym search (Places API (New) autocomplete + place details), saved as "Gym 1"
- Home screen: gym card, large SHOW UP button, Total Showups counter
- Location check: high-accuracy geolocation, Haversine distance, 100 m geofence
- Rejection of imprecise readings (accuracy worse than 100 m) unless the user is clearly far away
- Messages for: success, outside the geofence, poor accuracy, permission denied, position unavailable, timeout, unsupported browser
- Double-tap protection while a check is running
- localStorage persistence with validation, a recovery screen for damaged data, and a "continue without saving" option when storage is blocked
- Change gym; log out & reset (with confirmation)
- Dark, mobile-first MUI theme with ripples and transitions disabled

## Main technical decisions

| Decision | Why |
|---|---|
| No router; `App.tsx` picks the screen from state | Only three screens, and each one is determined entirely by saved data. |
| One `useShowup` hook instead of Context/Redux | One source of truth with no extra libraries. |
| Attendance rules in plain functions (`attendanceService.ts`) | Testable without React; portable to a backend. |
| Counter derived from event history | The counter and the history can never disagree. |
| Gym has its own `id`, separate from `googlePlaceId` | Events don't depend on Google identifiers; gyms not from Google remain possible. |
| Places API (New) via `@googlemaps/js-api-loader` | The current, officially supported API, with session tokens to keep billing sensible. The MUI `Autocomplete` keeps the look consistent. |
| Hand-written localStorage validation | Avoids adding a schema library for four small types. |
| "Clearly outside" overrides poor accuracy | Someone 5 km away with a vague signal is told they're not at the gym, rather than to "retry". |
| `schemaVersion` + versioned storage key | Allows a future migration. |

The example values above are illustrative. See `src/types/index.ts` for the TypeScript definitions.

## Known bugs and limitations

- Not real authentication; one shared profile per browser.
- Data is only in this browser; there's no sync or backup.
- Location can be spoofed (dev tools, emulators, spoofing apps). Reported proximity ≠ a workout.
- Google's single coordinate per gym may be more than 100 m from parts of very large venues.
- No limit on Showups per day.
- Geolocation requires HTTPS or localhost, so testing on a phone over a LAN IP doesn't work (see README).
- Changing your gym keeps your old Showups in the total (they keep the old gym's `gymId`).
- Production JS bundle ≈ 535 kB (≈ 170 kB gzipped); Vite prints a chunk-size warning.

## Manual testing checklist

Use Chrome or Edge with DevTools open. Record ✅ / ❌ and notes.

**Setup and identity**

- [ ] `npm run dev` starts and the app opens at http://localhost:5173
- [ ] Continue with an empty username → "Enter a username." error
- [ ] Continue with an empty password → "Enter a temporary password." error
- [ ] Valid username + password → gym setup screen
- [ ] DevTools → Application → Local Storage → `showup:data:v1` contains the username and **no password**
- [ ] Reload → still on gym setup (session restored)

**Google Maps**

- [ ] With no key in `.env` → "Google Maps is not set up yet" message, no crash
- [ ] With a valid key: typing 1–2 characters → "Type at least 3 characters"
- [ ] Typing a real gym name → real suggestions appear
- [ ] Typing nonsense (e.g. `qzxqzxqzx`) → "No places found…"
- [ ] Picking a suggestion → name and address shown, Save as Gym 1 enabled
- [ ] Save → home screen shows the gym name and address
- [ ] Reload → home screen, gym still saved
- [ ] With an invalid key or offline → an error message, no crash

**Show Up**

- [ ] DevTools → Sensors → set location to the gym's coordinates → SHOW UP → "You showed up!", count +1
- [ ] Set location ~1 km away → "You're not at your saved gym. Please go to Gym 1 and try again.", count unchanged; OK dismisses
- [ ] Block location permission for the site → explanatory message, count unchanged
- [ ] Sensors → "Location unavailable" → explanatory message, count unchanged
- [ ] Button shows "Checking location…" and is disabled while checking; rapid taps add at most 1
- [ ] Reload → count and events (Local Storage) unchanged
- [ ] On a real phone over HTTPS at the gym → success

**Reset and recovery**

- [ ] Change gym → setup with Cancel; Cancel returns home unchanged; saving a new gym updates the home screen
- [ ] Log out & reset → confirm dialog; Cancel keeps data; Reset → welcome screen, storage key removed
- [ ] Edit the Local Storage value to `{bad` and reload → "Saved data could not be read"; Reset recovers

**Layout**

- [ ] 360 px wide (DevTools device toolbar): no horizontal scroll, button easy to tap, counter directly below
- [ ] Desktop width: content centred and readable
